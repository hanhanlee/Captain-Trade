# 交易日誌同步誤刪持股修正（2026-06-24）

## 症狀
持股監控中「欣興 3037」的紀錄莫名消失。原本持有 3.5 張（3500 股），
某天打開系統後整列不見；今天再記一筆買進 1000 股時，又新建出一列只有 1000 股的紀錄。

## 根因
`pages/6_交易日誌.py:20` 在頁面載入時無條件執行
`modules.journal.sync_open_trades_to_portfolio()`。

舊版這個函式會：
1. 用**交易日誌**的買賣紀錄做 FIFO，反推每檔目前的開放部位；
2. 對日誌裡出現過的股票，**回頭刪除或覆寫**持股監控既有列
   （FIFO 淨部位 ≤ 0 → `sess.delete(row)`）。

問題在於**交易日誌不是持股的完整來源**。許多部位是早期累積、從未記進日誌。
以 3037 為例，持股監控原本記錄 7500 股（大多未入日誌），但日誌裡只有：

| 日期 | 動作 | 股數 |
|---|---|---|
| 2026-06-08 | 買進 | 478 |
| 2026-06-12 | 賣出 | 4000 |

FIFO 一算：買 478、賣 4000 → 淨部位 ≤ 0 → 開啟交易日誌頁時，
持股監控裡實際仍有 3500 股的那列被整列刪除。

時間線（以 Google Drive 備份比對）：
- `srock_backup_20260611`：3037 = 7500 股 @ 均價 388.6（正確）
- 6/12 09:58 記賣出 4000 → 應剩 3500 股
- 6/12～6/16 間開啟交易日誌頁 → 整列被刪
- `srock_backup_20260616` 起：已無 3037 列
- 6/24 13:36 記買進 1000 → 因原列不存在，新建成只剩 1000 股

而且這不是一次性意外：**只要再打開交易日誌頁就會再刪一次**。

## 修正
`sync_open_trades_to_portfolio()` 改為**純補入（additive-only）**：
- 只新增持股監控裡尚未存在的股票（缺漏才補）；
- **絕不刪除、也不覆寫**任何既有持股列；
- 既有部位的校正改由使用者在 UI 自行維護。

移除了會刪除/覆寫既有列的 `existing_rows` 迴圈，只保留「新增缺漏股票」的部分。

## 教訓
任何「用交易紀錄反推 / 校正持股」的功能，都要假設日誌不完整——
只能做加法補漏，不可拿不完整的反推結果去刪除或覆寫使用者的真實持股。
