## 第二十三章：事件日誌 — 決策時間線與 AI 分析匯出

> 「如果不記錄決策過程，回頭只能看到結果，看不到原因。」

### 什麼是事件日誌

事件日誌是系統的**黑盒子紀錄器**，自動把以下重要事件記錄下來：

| 事件類型 | 觸發時機 | 說明 |
|---------|---------|------|
| `scan_completed` | 每次選股雷達掃描完成 | 記錄策略版本、所有門檻參數、資料狀態快照 |
| `stock_selected` | 每檔入選股票 | 記錄 rank、score、觸發的條件、關鍵指標數值 |
| `near_miss` | 接近但未完全入選的股票 | 可用來了解「差哪些條件沒過」 |
| `alert_triggered` | 持股監控觸發警示 | 記錄警示等級、原因、當下股價 |
| `risk_check_passed` | 交易計畫通過風控 | 記錄通過的規則與參數 |
| `risk_check_failed` | 交易計畫風控未通過 | 記錄哪條規則未通過及原因 |
| `trade_plan_created` | 建立新交易計畫 | 記錄進出方向、價位、張數、理由 |
| `trade_executed` | 執行交易計畫 | 記錄實際成交價與對應日誌 ID |
| `user_cancelled` | 取消交易計畫 | 記錄哪個計畫被取消 |
| `notification_sent` | LINE / Telegram 推播成功 | 記錄推播類型與數量 |

---

### 為什麼需要事件日誌

只看交易結果，無法回答：
- 這支股票當初為什麼被選出？用的是哪版策略？
- 系統曾發出警示，但我有沒有照做？
- 被風控擋下的計畫後來是漲是跌？
- 我常常在什麼情況下違反自己的規則？

**事件日誌的價值：把「結果」往前追溯到「訊號、策略、風控、推播、使用者決策」的完整流程。**

---

### 使用事件日誌頁面

開啟側邊欄的「📋 事件日誌」頁面（第 11 頁）：

#### 篩選條件

| 篩選項目 | 說明 |
|---------|------|
| 日期範圍 | 選擇查詢的起訖日期，預設近 30 天 |
| 事件類型 | 下拉選擇特定事件（留「全部」則全查） |
| 股票代碼 | 輸入特定股票代碼，只顯示該股事件 |
| 模組 | 依來源模組篩選（scanner / portfolio / trade_plan / scheduler）|
| 嚴重度 | `info`（一般）/ `warning`（警告）/ `danger`（危險）|

#### 展開查看 payload

每筆事件都有 **payload**（詳細資訊），包含當時的策略參數、指標數值、風控結果等。

選擇一筆事件後，頁面左側顯示基本欄位，右側顯示完整 payload JSON，可以看到例如：
- 這次掃描的 RS 門檻是 80 還是 75？
- 這檔入選股的 ATR 是多少？連買了幾天？
- 風控規則 R4 的實際風險百分比是多少？

#### 掃描批次時間線（scan_id 鑽取）

每次掃描的所有事件（`scan_completed` + 所有 `stock_selected`）共享相同的 `scan_id`。

在「掃描批次時間線」下拉選單選擇一個 scan_id，可以看到那次掃描的完整事件流水——掃描完成、共幾檔候選、每檔的排名與分數。

### 匯出供 AI 分析

頁面底部提供三種匯出格式，適合不同用途：

| 格式 | 說明 | 適合場景 |
|------|------|---------|
| **CSV** | payload 展開成獨立欄位 | 用 Excel 預覽，或上傳 AI 做表格逐欄分析 |
| **JSON** | payload 保留完整巢狀結構 | 程式處理或 API 使用 |
| **JSONL** | 每行一筆事件（AI 友善格式）| **最適合直接貼給 Claude / ChatGPT 分析** |

#### 匯出步驟

1. 在頁面上方設定篩選條件（例如：近 90 天、事件類型「stock_selected」）
2. 設定「最多匯出筆數」（0 = 全部，最多 10,000 筆）
3. 點「⬇️ 下載 JSONL」，儲存到本機
4. 開啟 Claude 或 ChatGPT，上傳檔案，開始提問

#### AI 分析提示範例

下載事件日誌後，可以這樣問 AI：

```
這是我近 3 個月的選股事件記錄（JSONL 格式）。
請分析：
1. 哪些股票最常被選中？
2. score 超過 120 的股票有哪些共同特徵？
3. 哪個 scan_id 的入選股票最多？用了哪些設定？
```

```
這是我的交易計畫與風控事件記錄。
請分析：
1. 我最常違反哪條風控規則？
2. risk_check_failed 的事件中，失敗原因的分佈如何？
3. 我有多少比例的計畫最終執行了，有多少被取消？
```

```
這是我的持股警示紀錄（alert_triggered 事件）。
請分析：
1. 哪些股票觸發 danger 等級警示最多次？
2. 警示通常在什麼時間段密集？
3. 有哪些警示類型我需要特別注意？
```

---

### 注意事項

- 事件日誌是**附加紀錄**，不影響選股雷達、持股監控、交易日誌等現有功能
- 每次掃描才會產生新記錄，歷史補錄不在系統設計範圍內
- payload 的策略參數快照只代表**當時的設定**，未來版本若調整了門檻，舊事件仍保留當時值
- 日誌會持續累積，建議定期匯出後做 AI 分析，而不是等到資料量很大再一次查
