## 第二十五章：盤中 N 字底突破監控

### 這個模組在做什麼

針對台股科技類股，每日開盤前自動掃描出所有「已形成 N 字底結構（A→B→C）但尚未突破」的候選股，盤中每分鐘檢查是否突破 B 點，一旦發生立刻推送 Telegram 警示。

**N 字底定義（依 `ref/N字底_明確定義.md`）：**
- A：第一個低點（前段下跌的底）
- B：A 之後的第一個高點（反彈高點）
- C：B 之後的第二個低點，且 **C ≥ A**（不破前低）
- D：突破 B 的當下價（D > B 即視為完成）

量能輔助確認（不作硬過濾，僅在訊息中以 ✓/✗ 顯示，供使用者參考）：
- A→B 應量增（反彈有量）
- B→C 應量縮（回測量能轉冷）
- D 突破當下應量放大（與 B→C 平均量比較）

### 三層 pipeline 架構

| 階段 | 何時跑 | 做什麼 |
|---|---|---|
| **P1 候選清單建構** | 每週一到週五 **08:00**（開盤前 1 小時） | 拉科技股日 K → fractal 演算法找 A/B/C → 過濾 actionable（C 不超過 15 日、現價在 B 下 8% 以內或剛突破 1.5% 以內）→ 寫入 `n_pattern_watchlist` |
| **P2 盤中突破偵測** | 9:00–13:30 **每分鐘** | 對 watchlist 中尚未推播者批次取 Shioaji 報價 → D > B 即觸發 → Telegram 推播 → 標記 `alerted_today` 防重複 |
| **P3 監控頁面** | 隨時手動 | `pages/13_盤中N字底.py`：服務狀態、今日候選、警示歷史、手動重建 / 立即檢查 |

### Telegram 警示訊息範例

```
🎯 盤中 N 字底突破：3467 台灣精材（10:23）
產業：半導體業
─ 結構 ─
  A=40.00(04-15) → B=71.00(04-25) → C=56.00(05-02)
  B 漲幅 +77.5%　C 回測 48%
─ 量能驗證 ─
  A→B 量增：✓
  B→C 量縮：✓
  今日累積量：1.40× （B→C 日均量基準）
─ 現價 ─
  72.00（突破 B +1.41%）
⚠ 留意假突破：突破後若快速跌回 B 以下，可能為誘多
📊 報價來源：Shioaji
```

### 設計決策（重要）

- **不加防禦緩衝**：嚴格 D > B（無 B × 1.005），避免錯過剛突破第一根；以「⚠ 留意假突破」文字提醒人工判斷誘多。
- **Shioaji 未登入時整輪略過**：不 fallback 到 FinMind 個別取價（保護配額），事件日誌會記錄但不會錯誤推播。
- **樂觀標記**：先 `mark_alerted` 再送 Telegram，避免推播失敗的重試期間每分鐘都重推。Telegram 失敗仍保留 `alerted_today=True`，需手動或隔日 watchlist 重建才會重新觸發。
- **共用排程節奏**：P2 與盤中持股監控（portfolio monitor）共用同一個分鐘排程器（`scheduler/intraday_service.py`），共用 Shioaji 連線。
- **產業範圍**：預設 9 大科技類別（半導體、電子零組件、電腦及週邊、光電、通信網路、電子通路、資訊服務、其他電子、電子工業）。

### actionable 過濾參數

| 參數 | 預設 | 用途 |
|---|---|---|
| `max_c_age_days` | 15 | C 形成後超過幾天視為過時（突破動能消散） |
| `max_distance_to_b_pct` | 8.0 | 現價距 B 多少 % 以內仍值得追蹤 |
| `max_above_b_pct` | 1.5 | 已突破多少 % 以內仍納入清單（剛突破當天追進） |
| `min_b_rise_pct` | 5.0 | A→B 漲幅最小門檻（排除微幅反彈） |
| `min_c_retrace_pct` | 30.0 | C 對 A→B 的回測比例最小門檻 |
| `fractal_k` | 3 | fractal swing 偵測左右各 k 根 K 線比較 |
| `lookback` | 80 | 偵測往回看幾根日 K |

### 操作流程

**每日早上：**
1. 08:00 排程自動建構 watchlist，建構完成會推一則 Telegram 摘要訊息（scanned/hits/written）。
2. 開啟 `pages/13_盤中N字底.py` 檢視今日候選清單，依距 B% 排序預先決定觀察哪幾檔。
3. 9:00 開盤後排程自動每分鐘檢查，突破即收到 Telegram 警示。

> **晚開機自動補做（2026-06-08 起）**：08:00 watchlist 建構 job 設定 `misfire_grace_time=1800`（30 分鐘）+ `coalesce=True`。08:30 以前啟動 scheduler 都會自動補跑；超過則跳過（避免盤中才建出半套清單），需要手動跑「立即重建」。

**手動工具（頁面下方）：**
- **立即重建**：適用於排程錯過、想立即驗證新參數、或當日臨時想跑。
- **立即檢查**：手動觸發一次盤中突破檢查，繞過 cron 節奏（仍受 Shioaji 是否登入限制）。

### 警示歷史與審視

頁面下方「突破警示歷史」分頁可查看近 14 天：
- **突破推播**：每筆突破事件，含現價、B 價、今日量、BC 日均量
- **watchlist 建構**：每日建構統計（scanned/hits/written/skipped_*/errors）

底層資料來源是 `event_log` 中的 `n_pattern_breakout_alert` / `n_pattern_breakout_alert_failed` / `n_pattern_watchlist_built` 三類事件，可在「事件日誌」頁面做更細的篩選與匯出。

### 已知限制

- **Shioaji 必須登入才能跑 P2**：使用者帳號或 CA 憑證若未在當日上午登入，整個盤中檢查會安靜略過（Streamlit 頁面狀態會顯示）。
- **不偵測 W 底、頭肩底等其他型態**：本模組專注於 N 字底，其他型態需另外開發。
- **單純依日 K 結構判定**：不考慮基本面、法人、產業位階；交叉驗證請結合「個股分析」頁面。
