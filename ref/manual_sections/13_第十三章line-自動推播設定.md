## 第十三章：LINE 自動推播設定

### 推播種類與時間

| 時間 | 推播內容 | 觸發條件 |
|------|---------|---------|
| 週一至週五 09:00–13:30（每分鐘） | 盤中持股分K警示 | 觸及 MA5/10/20、停損、停利、（Shioaji 連線時）接近漲跌停 |
| 週一至週五 13:30 | 持股盤中警示 | 有任何警示訊號才發送 |
| 週一至週五 14:35 | 持股盤後警示 | 有任何警示訊號才發送 |
| 週一至週五 14:45 | 選股雷達結果前 5 名 | 每日固定發送 |
| 週一至週五 17:30 / 20:00 | ETF 持股快照更新 | 抓不到當日資料時推播待更新通知 |
| 週五 15:10 | 週績效摘要 | 每週固定發送 |

### 國定假日自動跳過（交易日守門）

排程器除了 cron 的「週一至週五」過濾外，**所有與盤勢有關的任務都會在每次觸發時再查一次台股官方交易日曆**。落在週一到週五但休市的國定假日（例如勞動節 5/1、農曆春節、國慶連假等），這些任務會直接 return 不執行，避免推送異常價格警示。

| 任務 | 是否套用交易日守門 | 備註 |
|------|------------------|------|
| 盤中分K監控（每分鐘）| ✅ | cron + 守門雙重過濾；每日只查 1 次 FinMind 交易日 API（in-memory 快取） |
| 持股警示（13:30 / 14:35）| ✅ | — |
| 盤後選股（14:45）| ✅ | — |
| ETF 持股更新（17:30 / 20:00）| ✅ | 抓「今日」快照的版本擋；補抓「前一交易日」的 08:10 不擋 |
| 週績效摘要（週五 15:10）| ❌ | 只統計過去交易紀錄，與當日盤勢無關 |
| 週五持股分佈（22:00）| ❌ | 抓近 180 天，少今日無感 |
| DB 備份（06:50）| ❌ | 每天都該備份，不受休市影響；備份期間會顯示 UI 警示，避免使用者寫入 DB |
| 手動點「執行一次盤中監控」| ❌ | 由使用者自負其責，方便在休市日驗證設定 |

> **失敗處理**：若 FinMind 交易日 API 暫時無法連線，守門邏輯會 log warning 後**保險起見視為交易日繼續執行**——寧可多送一則訊息，也不要在開盤日整批靜默漏掉。

### ETF 持股資料完整性（避免某次 miss 導致整天斷層）

ETF 持股快照採 **三層冗餘設計**，即使機器某段時間沒開或抓取失敗，也不會永久缺一天：

| 層級 | 觸發 | 抓什麼 | 用途 |
|------|------|--------|------|
| L1 同日自動 | 17:30 / 20:00（週一至五）| 今日快照（內部各 3 輪重試）| 當晚就能看到變化 |
| L2 隔日自動補抓 | 08:10（週二至六，`use_today=False`）| **前一交易日** | L1 完全 miss 時的兜底，只要早上機器有開機就會跑 |
| L3 UI 手動補抓 | 選股雷達頁 → 「🏦 ETF 持股追蹤」→ **🟢 補抓缺漏日期** 按鈕 | 偵測近 7 個交易日缺漏，一次補齊 | 連假後或長期關機後使用，`skip_existing=True` 可安全重複點 |

> 因此即使你晚上 14:00 之後關機（17:30 / 20:00 都 miss），隔天 08:10 也會自動把昨天的補上；再不行，選股雷達頁的缺漏列表會直接顯示「✓ 完整」或「需補抓」，點按鈕即可補齊。

> **misfire 容錯（2026-06-08 起）**：L2 的 08:10 job 設定 `misfire_grace_time=1800`（30 分鐘）+ `coalesce=True`。早上晚開機只要在 08:40 前啟動 scheduler，08:10 的補抓仍會自動觸發；超過則跳過避免和 08:50 V3 watchlist 撞資源。

### 手動觸發推播

如果不想等自動時間，可以在「市場環境」頁面的「排程控制」頁籤，隨時手動觸發任何推播任務。

### 訂閱者管理（新版）

現在推播不再只綁定單一 `LINE_USER_ID`。系統改成：

- **群播模式**：所有 `已啟用` 的訂閱者都會收到選股、警示與週報
- **單人測試**：可在「7 - 資料管理」頁面對單一訂閱者送測試訊息
- **停用不中斷紀錄**：暫停接收時，不需要刪除資料
- **向下相容**：若資料庫沒有任何訂閱者，仍會 fallback 到 `.env` 的 `LINE_USER_ID`

你可以在「7 - 資料管理」頁面：

- 查看所有訂閱者
- 個別啟用 / 停用群播
- 新增或刪除 LINE User ID
- 立即送出測試訊息確認 Bot 是否正常

### Webhook 自動訂閱

如果你有啟動 `webhook.py` 並在 LINE Developers Console 設定 Webhook URL，使用者可以透過 Bot 自動加入或暫停群播：

| 事件 / 指令 | 系統行為 |
|------------|---------|
| 加 Bot 好友 | 自動加入訂閱者清單 |
| 傳送任意訊息 | 若尚未訂閱，會自動加入 |
| `我的ID` | 回覆自己的 LINE User ID |
| `取消訂閱` | 停用群播，但保留紀錄 |
| `重新訂閱` | 重新啟用群播 |
